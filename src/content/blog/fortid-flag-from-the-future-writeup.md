## 题目背景

题面是一段「找不到回退键」的吐槽：

> I found this neat drawing program online and wrote the flag using one of my favorite fonts（[DejaVu](https://dejavu-fonts.github.io/)）🎨。I pressed the play button, and before I could react, the flag transformed itself into these weird shapes. Why is there no rewind button!? Can you help me recover the flag?

附件只有一张 `screenshot.png`（3062×288）。README 的 Note 交代了全部规则：

> flag 用 [DejaVu 2.37 TTF](https://sourceforge.net/projects/dejavu/files/dejavu/2.37/dejavu-fonts-ttf-2.37.zip/download) 其中一个字体、在**整数像素尺寸**下渲染；**每个强度 ≥ 50% 的光栅像素成为一个活细胞**。然后按下 play 跑了康威生命游戏，截图是跑完之后的状态。

所以这是一道**逆向元胞自动机**题：正向 =「文字 → 字体光栅化 → 活细胞 → 跑 N 代生命游戏」，要我们从末态「倒带」回初态，读出那串文字。

## 分析

**第一步永远是把截图还原成「真正的元胞网格」**，而不是对着一堆色块猜。

截图里每个活细胞被画成一个 6×6 像素的方块，方块之间留 2px 间隙，所以**网格步距（pitch）是 8px**。我用行/列投影找活像素的游程，确认了：

- 活块宽度恒为 6px，相邻活块起点间距都是 8 的倍数（8/16/24…）；
- 列方向活块起点 ≡ 7 (mod 8)，行方向 ≡ 0 (mod 8)。

据此按 8px 步距重采样，得到一张 **36 行 × 382 列** 的 0/1 元胞矩阵，共 **909 个活细胞**，有效区域是第 4–30 行（高 27 格）、第 6–376 列（宽 371 格）。这 27 格高、371 格宽正好对应「一行约 27 个字符、字号 ~27px 的 flag 文本演化后的样子」。

**这一步是扎实的、确定的成果**——末态网格是精确的。难点全在「怎么倒带」。

逆向康威生命游戏本质很难：

1. **它是多对一映射**，一个状态可能有多个前驱，也可能一个前驱都没有（「伊甸园」态）。通用的一步逆推都要上 **SAT 求解器**（z3 / MiniSat）去枚举前驱。
2. **演化代数 N 未知**。截图里细胞已经高度离散、出现了滑翔机和碎片，说明跑了不止一两代。盲目逆推 N 步，搜索空间爆炸且前驱不唯一。
3. **真正的约束来自「初态必须是某串 ASCII 用 DejaVu 2.37 在整数像素尺寸下的光栅化结果」**——正是这条约束让问题从「不可解」变成「有限可搜」：我们不是在任意 0/1 网格里逆推，而是在「可被某个字符串渲染出来」的极小子集里搜。

## 关键点 / 解法

核心利用的是**生命游戏的局部性**：每一代，一个细胞的状态只受 3×3 邻域影响，信息每代最多向外扩散 1 格。因此跑 N 代后，初态里相距超过 `2N` 的两块区域，其后代**互不重叠、各自独立演化**。

flag 文本里字形之间天然有间隙（字母之间、尤其 `{` `_` `}` 周围）。只要字间距 > 2N，就能把末态**按字形切成一段段**，**逐字符独立暴力**：

> 对每个字符槽位，枚举所有可打印字符 → 用 DejaVu 2.37 在标定好的字号下渲染该字形 → 正向跑 N 代 → 和该槽位的末态子图比对 → 完全吻合即还原出该字符。

这就把一个 NP 难的「逆推任意网格」问题，降维成「枚举约 95 个可打印字符 × 已知字形宽度推进」的线性扫描。需要先标定三个参数：**字体变体、整数字号 S、演化代数 N**。

标定可以利用已知前缀 `FortID{`：对每个 (font, S, N) 组合，渲染 `FortID{` 并正向跑 N 代，和末态的**最左区域**对齐比对，吻合度最高的那组就是正确参数（最左几个字形离未知部分远，在小 N 下不会被右边字符的演化污染）。参数定好后，从左到右维护一个「画笔 x 坐标」，逐槽位暴力字符、按字形 advance 宽度推进即可。

## 求解步骤（贴实际命令/脚本/读到的关键内容）

```python

b = (np.array(Image.open("screenshot.png").convert("L")) >= 128).astype(np.uint8)
H, W = b.shape
xs = range(7, W-5, 8); ys = range(0, H-5, 8)      # 列起点≡7、行起点≡0 (mod 8)
grid = np.array([[1 if b[y:y+6, x:x+6].mean() >= 0.5 else 0 for x in xs] for y in ys], np.uint8)
# grid.shape == (36, 382)，grid.sum() == 909；有效区 27 行 × 371 列
```

**我实际跑到的进度**：第 1–3 步完全成功——末态 36×382/909 活细胞已精确提取，DejaVu 2.37（22 个 TTF）已下到本地，生命游戏引擎可用。到第 4 步标定时卡住了：我对 10 个 DejaVu 变体 × 字号 20–33 × N=1–21 做了前缀 `FortID{` 的对齐搜索，**最优 IoU 只有约 0.18、最左 40 列里有 ~92 个细胞对不上**，即任何一组参数都无法让「渲染前缀再演化」对上末态左区。

原因分析（也是这题离线复现的真正障碍）：

- **「在线绘图程序」的光栅化方式未知**：抗锯齿、hinting、阈值取舍跟我用 PIL/FreeType 的渲染不完全一致，导致连**初态位图**都无法逐像素复刻，后面逐字形精确比对自然对不上；
- **演化代数 N 偏大**：末态已明显离散出滑翔机/碎片，N 不小；N 一大，前缀单独演化就会和真实情形（右邻字符参与演化）快速发散，最左区也未必「干净」；
- 逆向本身的多前驱 / 伊甸园态问题，使得不借助精确正向模型就无法唯一确定。

## 小结 / 收获

- 逆向元胞自动机的「破局点」不是硬逆，而是**附加约束**：初态必须是「可被某字符串渲染出来的位图」，这把搜索空间砍到可枚举；再叠加**生命游戏的局部性**，就能从「逆推整张图」降到「逐字形暴力」。
- 这类题**正向廉价、逆向昂贵**，所以永远优先构造正向模型去匹配，而不是直接去解逆问题。
- 复现的成败高度依赖「能否逐像素复刻初态」：字体版本、字号、抗锯齿/阈值、渲染器任何一处不一致，逐字形精确比对就会整体崩掉——这也是我这次卡住的根因，值得记一笔。
- 已沉淀的确定成果：末态 = 36×382 网格、909 活细胞、有效区 27×371；字间步距 8px、活块 6px、阈值 128（=50%）。这些是下次接着做的可靠起点。
