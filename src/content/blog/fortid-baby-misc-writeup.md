> Flag: `FortID{D0_or_D0_N07_Th3r3_15_n0_Tri3}`（这题我确实从本地下载的压缩包里提取到了确定结果，所以这里给出真实 flag）

## 题目背景

题面是一句挑衅："Heard you're a M4st3r H4ck3r, can you re**trie**ve the flag from this archive?"，附一个 Google Drive 链接。注意 README 里把 **trie** 三个字母加粗——这是最大的提示词：`re`**`trie`**`ve` → **trie（字典树）**。标题还自带"从 archive 里取 flag"的方向。

## 线索分析（真实动手）

下载的文件是不可信数据，我把它单独放进一个空目录，所有脚本都放在另一个目录，python 一律加 `-I` 运行，路径当参数传。

**1. 确认文件类型**

```
file download.bin
→ Zip archive data, compression method=store
```

344 MB、全部 `store`（不压缩）。用 `xxd` 看头部，第一个条目名很可疑：

```
retrieve/81/81/68/86/95/90/104/67/98/84/104/103/40/...
```

目录名全是**十进制数字**，一看就是 ASCII 码。`chr(81)='Q'`、`chr(68)='D'`…… 把一条路径拆开按 ASCII 解码，得到的是一串随机字符。

**2. 枚举条目（用 `zipfile` 读中央目录，不解压）**

- 共 **7000** 个条目，每个都是 `.png`，大小**全部一模一样 = 48857 字节**。
- 每个文件名都形如 `retrieve/<code>/<code>/.../eow.png`，末尾固定有一个字面量 `eow`（end of word，词尾标记）。
- 把 7000 条路径全部解码成"词"，结果都是带着 `{`、`}`、`:` 的**随机乱码**——这些是诱饵（decoy），对应标题的"trie"：一棵塞满假词的字典树。

**3. 看图片本体**

渲染其中几张 PNG，发现它们是**同一张梗图**：一个戴帽衫的人趴在干草堆里，墙上写着 `REAL FLAG SOMEWHERE IN HERE ↓`，马克杯上写着 `still looking`。也就是说，**像素内容都一样，针不在画面里**，而在这 7000 个文件的"差异"里。

**4. 找差异 → 定位针**

7000 张图肉眼相同，但 CRC 有 6635 种，说明文件之间有细微差别。逐个解析 PNG 的 chunk，发现每个文件都带**一个 `tEXt` chunk，keyword 固定为 `Comment`**，值是一长串十六进制。关键一步——统计这些 `Comment` 的长度：

```
value lengths: {236: 6999, 11171: 1}
```

**6999 个长度是 236，只有 1 个是 11171。** 这个长度异常的文件就是"针"。

**5. 读出 flag**

异常文件的**文件名本身**就是答案（其超长 tEXt 只是用来标记它、让它成为唯一异常值）。它的路径：

```
retrieve/70/111/114/116/73/68/123/68/48/95/111/114/95/68/48/95/78/48/55/95/84/104/51/114/51/95/49/53/95/110/48/95/84/114/105/51/125/eow.png
```

按 ASCII 逐段解码：

```python
p='70/111/114/116/73/68/123/68/48/95/111/114/95/68/48/95/78/48/55/95/84/104/51/114/51/95/49/53/95/110/48/95/84/114/105/51/125'
print(''.join(chr(int(x)) for x in p.split('/')))
# FortID{D0_or_D0_N07_Th3r3_15_n0_Tri3}
```

> **Flag：`FortID{D0_or_D0_N07_Th3r3_15_n0_Tri3}`**

flag 内容是尤达的名言 "Do or do not, there is no try"，正好呼应 `re`**`trie`**`ve` / trie 的梗——"没有 try（trie），只有做"。

## 解题思路 / 该怎么做

一句话方法论：**在 7000 个诱饵里找"异常值"**。可操作步骤：

1. 下载到独立目录，`file` 确认是 ZIP，`store` 存储。
2. 用 `python3 -I` + `zipfile` 只读中央目录，不要盲目解压（344MB、几千文件）。
3. 观察路径是 ASCII 码 → 先别急着解每一条，先找**结构性异常**：
   - 文件大小是否全相同？（这里是）
   - 渲染几张图确认内容相同（梗图明示"针在里面"）。
   - 逐文件解析 PNG chunk，统计 `tEXt`/`zTXt`/`iTXt` 的**长度分布 / keyword / CRC**，异常的那一个就是针。
4. 对异常文件，优先看它**自身的元信息**：文件名、路径、超长字段。这里是把路径当 ASCII 码解出 flag。

备用思路：如果异常体现在图片像素（而非文件名），就 diff 像素；如果体现在 tEXt 内容，就 hex 解码那串十六进制看是否是另一层文件（PNG/ZIP 魔数）。本题 6999 个 236 长度的 hex 是纯诱饵，不用解。

## 小结 / 收获

- "大海捞针"类 Misc 的通法是**找分布里的离群点**：大小、CRC、chunk 数、字段长度、keyword，任选一个维度做直方图，异常立现，不用硬刚几千个样本。
- PNG 的 `tEXt` 是常见藏数据点，`zipfile`/`struct` 手搓解析比逐个 `unzip` 快得多。
- 标题里被**加粗/变形**的字母（re**trie**ve）往往直接点题，先读懂梗再动手。
